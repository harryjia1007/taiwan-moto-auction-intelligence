# Security Policy

## Supported versions

The default branch is supported while the project is pre-1.0. No released version should be assumed to receive long-term security updates yet.

## Reporting a vulnerability

Please do not open a public issue for a vulnerability, exposed credential, unsafe source-fetch behavior, or a report containing sensitive personal data.

Use GitHub's **Report a vulnerability** private security advisory flow for this repository. Include:

- affected component and commit;
- reproduction steps or a minimal proof of concept;
- likely impact;
- whether official-source or third-party systems could be affected;
- any suggested mitigation.

The primary maintainer aims to acknowledge a complete report within 7 days and provide a remediation decision within 14 days. Timelines may change for a volunteer-maintained project, but status updates will be provided through the private advisory.

## Scope boundaries

The project only supports public, read-only collection. Reports showing authentication bypass, CAPTCHA circumvention, unsafe URL fetching, secret leakage, cross-user data access, artifact injection, or incorrect Supabase row-level security are especially important.
