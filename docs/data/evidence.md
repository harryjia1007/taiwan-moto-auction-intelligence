# Evidence Specification

Every consequential field may have multiple evidence rows containing the entity and field, normalized value, source record, artifact, exact source text, page/table location, parser and version, extraction method, trust level, confidence, and timestamp.

When a parser uses more than one raw artifact for a record, `EvidenceRef.artifact_checksum_sha256` selects the exact immutable artifact that contains the quoted text. Local PostgreSQL persistence and the hosted Supabase publisher both recompute SHA-256 from the bytes and validate every evidence reference before the first database or Storage write; a forged checksum or absent artifact fails closed. Evidence without an explicit checksum retains the legacy primary-artifact behavior. A manually exported search index can contain several official records and is checksum-deduplicated into one shared `raw_artifacts` row; that row's `source_record_id` is only the first persistence owner, not a claim that the page contains evidence for only that case. Each `field_evidence` row still carries its own source record and points to the shared artifact by its exact checksum-derived ID. The fetched detail HTML remains first and is always the snapshot primary artifact.

Persisted extraction methods use only the database enum values `STRUCTURED`, `HTML`, `DOCUMENT_RULE`, `OCR`, or `LLM`. An outbound link found in official HTML is still `HTML` evidence; link handling is represented by its field and source policy, not by inventing another extraction-method literal.

When source policy permits only outbound access, the database stores an idempotent `OFFICIAL_LINK_ONLY` document row after exact source-specific host, path, scheme, port, query, and filename validation. The document remains a link to the official site; no PDF bytes are downloaded into project storage.

Exact evidence text remains owner-only. The anonymous projection is rebuilt from normalized facts and applies a second safety boundary that removes identifiers, role-labelled people, contact values and labelled private addresses without rewriting the immutable artifact or evidence row. The safety boundary recognizes Chinese and Latin names after common case roles, Taiwan mobile and segmented landline formats (including `+886`, parentheses and extensions), fullwidth national-ID text, and repeatedly percent-encoded identifiers in outbound URLs. An unrecognized value following a person-role label is withheld instead of being guessed safe. Official vehicle viewing/storage locations are not treated as private addresses merely because they contain a street name. This keeps traceability intact while preventing the public marketplace from becoming a copy of unnecessary personal data.

The public projection also masks plate-shaped text even if parsing missed a structured plate identifier. If an outbound URL or public source key contains an unparsed plate-shaped token, the URL falls back to the reviewed source homepage or the key becomes a stable opaque hash; exact Judicial main-site CMS route IDs and UUID-style document IDs are treated as route identifiers, not vehicle plates. Private artifacts and evidence keep the original values.

A human-reviewed Judicial manifest row is a transcription artifact, not bytes returned by an official API, query result, or PDF. Its explicit manifest values use `UNKNOWN` trust and parser-derived values use `SYSTEM_CALCULATED`; the official outbound PDF URL is retained separately for verification. Legacy artifacts demonstrably captured from the historical official query retain their original official trust. Customs title evidence points to the exact preserved list-page artifact, organization evidence points to the exact official overview artifact, and detail-only fields point to the detail artifact; checksum validation prevents any quote from being attributed to the wrong page.

Authority order is `OFFICIAL_EXPLICIT`, `CROSS_SOURCE_CONFIRMED`, `OFFICIAL_INFERRED`, `SYSTEM_CALCULATED`, `LLM_EXTRACTED`, `THIRD_PARTY_REFERENCE`, then `UNKNOWN`. Lower-authority evidence is retained when a winner is selected. Conflicting explicit official values remain visible and set the normalized fact to `CONFLICTING` where applicable.
