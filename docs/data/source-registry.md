# Source Registry

Statuses are `PLANNED`, `PARTIAL`, `ACTIVE`, `DEGRADED`, or `DISABLED`. `ACTIVE` means a live run completed successfully; code presence alone is insufficient.

Organization rows are seeded independently of adapter status so future sources can link to canonical agencies without changing application logic.

The database `source_access_policies` registry is the operational gate. Every row records a decision (`ALLOW`, `MANUAL_ONLY`, `REVIEW_REQUIRED`, or `DISABLED`), robots and terms locations, photo rights, personal-data risk, rationale, and review date. Both the local PostgreSQL repository and hosted Supabase publisher query that persisted row before creating a run or calling adapter discovery: automated collection requires exactly `ALLOW`, human-provided manifests require exactly `MANUAL_ONLY`, and a missing, duplicate, invalid, or different decision fails closed. The in-code policy remains a first gate, so neither a stale deployment nor a database-only change can silently broaden access. A healthcheck proving that a page is readable never changes this authorization decision. Access permission and republication permission are evaluated separately: Judicial Yuan's OGL declaration supports attributed reuse and ordinary linking, but it does not authorize automation against a path whose access policy disallows robots, nor does it cover excluded third-party media or remove Personal Data Protection Act duties.

Source-registry migrations add defaults only when an entry is absent. They must never overwrite an existing stricter access decision, `DISABLED` source status, or manually disabled endpoint. Re-enabling any such entry requires a separate, reviewed operator action after the source policy is checked again.

Anonymous source health comes only from the `public_source_health` projection written at the end of an actual hosted run. It contains aggregate counts, parse rate, last attempt/success, per-source staleness threshold and closed warning codes; detailed warnings, errors and endpoints remain owner-only. The public UI must show that health is unavailable when this projection cannot be read and must never infer a successful run from listing timestamps.

The MOJ `ALLOW` decision is host-scoped to `auction.moj.gov.tw`. Some historical central rows redirect to individual prosecutor-office hosts whose `robots.txt` endpoints currently redirect to ordinary HTML rather than publishing a usable robots policy. Those hosts are not inherited into the central allowlist. The collector does not contact them: it stores the exact vehicle row bytes already returned by the approved central list, publishes only fields proven by that row, and records a partial-detail warning. A changed list row that cannot be preserved fails explicitly.

`Government e-Procurement` is a nationwide distribution channel, not a disposal-origin label. A court selling its own obsolete scooter through PCC is `SCRAP_DISPOSAL`, not `JUDICIAL_EXECUTION`; a police notice for unclaimed impounded scooters is `IMPOUNDED_UNCLAIMED`. Only a record proven by its official court or Judicial Yuan notice may use `JUDICIAL_EXECUTION`, and that origin does not imply either judicial source has complete nationwide discovery. Administrative execution remains separate so the dashboard does not conflate legally different auctions.

The Judicial Yuan main-site `judicial_notices` adapter is a supplemental source distinct from the blocked `aomp109` application. It preserves bounded search-result and detail HTML from only `/tw/lp-1913` and `/tw/cp-1913`, requires explicit vehicle and auction semantics in each detail, and never fetches `/tw/dl-...html` attachments or images. Its healthy run cannot promote the separate 22-court source or imply nationwide completeness. Full boundaries are documented in [the Judicial Yuan other-notices specification](../ingestion/judicial-notices.md).

The two aomp109 URLs retained in `source_endpoints` are disabled provenance/manual-reference rows. A `judicial` run without a human-reviewed manifest is rejected before an HTTP client or source request exists; manifest fetch serializes only the supplied structured row and validates its official URL without opening it. Its healthcheck reports manual mode without probing aomp109. This database flag is defense in depth in addition to the `MANUAL_ONLY` policy and the absence of `judicial` from every unattended workflow.

The PCC `ALLOW` authorization is based specifically on the Public Construction Commission's published dataset 7263: free OGDL 1.0 XML updated each working day, not on an inference from robots alone. Live access is still fail-closed: every discovery must freshly load a valid same-host `robots.txt` and allow both the feed and each exact detail URL before contact. Discovery reads that feed once and filters only explicit vehicle terms. Exact detail resolution stays on `web.pcc.gov.tw` over HTTPS and must match all five published identity fields; ambiguous matches are rejected.

Administrative Enforcement branch CMS is a separate source from the central CAPTCHA search. Its allowlist contains exactly 13 named `*.moj.gov.tw` hosts, not a wildcard. Each run fetches that branch's robots file and declared same-host sitemap before following bounded homepage announcement links. Every redirect target is checked again against the loaded branch robots policy before it is contacted; a robots redirect before policy loading is rejected. An announcement-list response is counted as checked only when it contains the validated official table structure or an explicit official empty marker. Unknown markup fails closed, and an unvisited next page at the two-page safety bound makes the run partial instead of claiming complete discovery. Three consecutive preflight failures of the same connection/timeout type open a circuit breaker: the remaining branches are explicitly marked unchecked, the run is partial when an earlier branch succeeded and fails when none did, and prior records are retained. A partial branch outage is never reported as zero auctions.

The Government Data Portal catalog watcher is an operational monitor, not an auction source and therefore has no `sources` row or coverage status. It reads only the official dataset 6564 daily JSON catalog from the exact `data.gov.tw` HTTPS endpoint after scheduled source jobs finish. A recent entry must contain government-agency, auction and vehicle semantics; pure real-estate datasets are excluded. A match produces a non-failing human-review warning with only the dataset ID and official metadata URL. It never downloads the candidate dataset, creates a case, writes a public listing, or promotes coverage automatically. Network, redirect, MIME, size or catalog-structure validation failures fail the watcher without changing existing source health. Full boundaries are documented in [the catalog watcher specification](../ingestion/data-gov-catalog.md).

Customs collection covers the four official announcement lists and their HTML detail pages. List and overview HTML are preserved alongside each accepted detail so title and organization evidence refer to the artifact that actually contains the quoted text. Each office is bounded to five list pages and 100 rows per page; remaining official pages or rows produce an explicit partial-coverage warning instead of a claim of complete discovery. Because the current robots policy excludes `/download/`, the collector records those attachment URLs as official links but does not request or mirror their bytes. A vehicle mentioned only inside an attachment remains an explicit coverage gap.

The shared-policy `ALLOW` adapters (`shwoo`, `moj_auction`, `pcc`, and `customs`) reload their exact-host robots policy at the start of every discovery. A verified policy is cached only for requests within that operation; timeout, connection failure, 403/429, 5xx, invalid MIME/encoding, missing directives, excessive size, unsafe redirect or disallow fails closed and never falls back to a prior run's allow decision. Every contacted redirect target must remain same-host HTTPS on the default port and pass the loaded policy. The Judicial main-site and branch-CMS adapters enforce the same fresh-run/no-stale-fallback invariant through their source-specific robots and sitemap preflights.

Shwoo is a partial-coverage exception only for individual bounded keyword requests: a timed-out unrestricted/recycler query or a failed recent-result query keeps independently discovered AUIDs but records a warning, marks the run `PARTIAL`, and does not advance `last_successful_at`. It must not turn a failed query into an apparently complete zero-result search. Robots denial and 403/429 remain run-stopping policy responses.

The dashboard translates source states into user-facing Chinese: `ACTIVE` is `正式同步`, `PARTIAL` is `試運轉`, `DEGRADED` is `需注意`, `DISABLED` is `已停用`, and `PLANNED` is `未實作`. A source is never presented as formally online merely because adapter code exists. Administrative Enforcement central search remains manual-only; its 13-branch CMS source stays `PARTIAL` until every branch has completed a healthy scheduled run, because branch outages and CAPTCHA-gated central discovery prevent a claim of continuous nationwide coverage.
