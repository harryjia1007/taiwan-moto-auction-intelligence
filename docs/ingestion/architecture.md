# Ingestion Architecture

Adapters implement independent asynchronous discovery, fetch, parse, and healthcheck stages. A failed item is recorded without rolling back successful items, while a failed source never changes prior auction statuses.

Run health and access authorization are separate. Before any adapter discovery, the command checks the reviewed in-code policy and then queries the matching persisted `source_access_policies` row. Hosted automation accepts exactly `ALLOW`; human-supplied manifests accept exactly `MANUAL_ONLY`. Missing, ambiguous, invalid, or mismatched persisted state blocks the run before a `sync_runs` row or source request is created. Only an `ALLOW` source with a fully successful run can become `ACTIVE`; a mixed successful/failed run stays `PARTIAL`, and a failed run becomes `DEGRADED`. A clean human-assisted `MANUAL_ONLY` import may advance `last_successful_at`, but its source remains `PARTIAL`; `REVIEW_REQUIRED` remains `DEGRADED` and `DISABLED` remains `DISABLED` regardless of run outcome. Thus a valid manual import records freshness without misrepresenting automated coverage.

A source may safely parse a lower-completeness record after a deeper detail request is blocked. Such an item increments both `parsed` (the retained official summary) and `failed` (the unavailable detail stage), adds an explicit warning, and keeps the run `PARTIAL`. This deliberately distinguishes “the official central list proves the auction exists” from “all detail evidence was collected.”

Network safeguards include an HTTPS host allowlist, one-request-per-second pacing, two retries with bounded backoff, 20-second timeouts, a 25 MiB artifact limit, checksum-addressed writes, MIME validation, and per-hop redirect validation. The shared robots implementation used by `shwoo`, `moj_auction`, `pcc`, and `customs` freshly fetches exact-host `robots.txt` at every discovery with a 10-second timeout, 256 KiB limit, UTF-8 and `text/plain` validation, no more than three same-host HTTPS redirects, and an explicit `User-agent` requirement. The Judicial main-site and branch-CMS adapters perform equivalent source-specific fresh-run preflights. A successful parser is cached only inside that adapter operation; no stale allow policy is reused after reset or a failed refresh. Every target and same-host redirect target is rechecked with `can_fetch` before contact; if no verified policy has been loaded, the request is rejected. Downloads are treated as bytes; scripts and macros are never executed. Storage writes are idempotent only when Supabase returns its exact duplicate-object signature (`409` / `Duplicate` / `KeyAlreadyExists`); authorization, bucket, and all other upload failures remain run failures.

`python -m ingest sync --source <key>` runs each implemented source in isolation. The hosted matrix is configured for five `ALLOW` candidates—`moj_auction`, `pcc`, `customs`, `moj_enforcement_cms`, and `judicial_notices`—but none is considered hosted-operational until the deployed migration ledger, secrets, successful workflow conclusion, matching database run, persisted artifacts/snapshots, and public health row are checked. `shwoo` remains an approved owner-operated Taiwan-network batch source because GitHub-hosted full discovery repeatedly timed out. Every public publisher preserves private artifacts and snapshots before updating the sanitized projection. PCC reads official dataset 7263 XML once per run and resolves only an exact five-field same-host HTTPS match. Customs reads the four official HTML channels but never fetches `/download/` attachments. Administrative Enforcement branch discovery preflights each of 13 explicitly registered CMS hosts. Judicial main-site supplemental discovery preflights `www.judicial.gov.tw`, searches only the recent `/tw/lp-1913` notice window, fetches exact `/tw/cp-1913` vehicle-auction details, and treats `/tw/dl-...html` as link-only evidence; it never contacts `aomp109`. The separate `moj_enforcement` path parses human-saved central result HTML entirely offline or accepts a validated detail manifest; it never requests central Query, submits CAPTCHA, follows redirects, fetches images, or mirrors PDF bytes. `healthcheck` is bounded and reprocessing normally consumes stored artifacts without live discovery. Central Administrative Enforcement is the exception: until the shared export-to-record association is modeled independently, it fails closed and requires re-importing the original saved result HTML.

Discovery warnings are first-class run state. If one branch or list fails, or an official next page remains after a configured safety bound, the run is `PARTIAL` even when other cases were parsed. If discovery itself raises before any record can be parsed, the run is `FAILED`. Neither condition deletes prior records or advances a misleading successful timestamp.

During per-record fetch or parse, an official HTTP 403, 429, or live robots denial stops the remaining records for that source's current run. Already saved records remain intact; the stopped run records one access failure, stays `PARTIAL` when earlier records succeeded or `FAILED` when none did, and the hosted command exits nonzero. Other sources remain isolated in their own scheduled jobs. Ordinary per-record parse or transient detail failures remain item-scoped, so one malformed notice does not erase unrelated official records.

The marketplace read model unions identified vehicles with inseparable official lots. A bulk notice without separable identities remains a lot and may be displayed, but it cannot be favorited as a made-up vehicle.
