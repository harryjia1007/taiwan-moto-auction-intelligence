# Paste-ready Claude Design prompt

```text
你是一位資深產品設計師、UX 工程師與資訊視覺化設計師。請重新設計「臺灣機車拍賣情報」私人情報台。這不是一般中古車電商，而是協助單一已登入使用者，從臺灣法院法拍、公務機關財物變賣、移置保管逾期未領車輛與臺北惜物網中，快速找出值得進一步查證的機車。

核心任務不是讓畫面看起來熱鬧，而是讓使用者在 30 秒內回答：
1. 我能不能投標？
2. 得標後能不能過戶、重新領牌或上路？
3. 價格、拍次與截止時間是什麼？
4. 車況、鑰匙、發動、測試、里程與照片知道多少？
5. 還缺哪些重要資料？
6. 哪一段官方原文支持這個判斷？

請使用附上的 sample-marketplace-data.json 與 data-contract.md。不可自行補值；UNKNOWN 必須顯示「未確認」，不能當成 NO，也不能隱藏。頁面消失或期限已過不能標成 SOLD，只有官方明示成交才可顯示「已成交」。整批標售若沒有可分離車輛身分，必須維持一個 lot，不能發明多台車。

需要設計的畫面：
- 桌機 1440px：進行中機車列表與篩選工作台
- 手機 390px：第一屏即可搜尋、切換進行中／歷史／收藏，進階篩選可收合
- 桌機 1440px：機車詳情與官方證據
- 手機 390px：詳情頁，底部固定「核對官方公告」主要行動
- 資料來源健康狀態：ACTIVE／PARTIAL／PLANNED、最後同步、解析率與警告

列表資訊優先順序：
P0：投標資格、領牌／過戶狀態、價格類型與金額、截止時間、是否整批。
P1：官方照片、廠牌型號、出廠年月、排氣量、車牌、地區、機關。
P2：鑰匙、發動、測試、里程、主要風險、資料完整度。
P3：來源名稱、處分性質與其他次要 metadata。

互動要求：
- 所有搜尋、來源、縣市、資格、領牌、照片、整批、價格、期限與排序狀態都在 URL，可書籤與返回。
- 提供「一般人可買、可上路優先」「有照片的單台車」「7 天內截止」「法院法拍」快捷條件。
- 手機不要讓介紹文與表單占滿第一屏；搜尋與案件狀態必須最先可操作。
- 收藏要有 loading、成功與失敗狀態。
- 重要欄位可連到詳情頁中的官方證據。
- 詳情頁先呈現 decision brief，再呈現完整規格、費用、歷史與證據。
- 官方公告連結是主要行動，但需明確標示會離開本站。

視覺方向：高級但克制的情報工作台，結合精品機車雜誌的編輯感與專業金融終端的資訊效率。使用暖灰紙張、深墨綠、炭黑與少量銅色；繁體中文排版必須舒服。避免紫色漸層、霓虹、玻璃擬態、過度圓角、每個元素都是膠囊、巨大的置中 hero、裝飾性儀表板圖表與常見 AI SaaS 風格。陰影要少，靠字級、留白、線條與色彩語意建立層級。

狀態顏色必須有文字，不可只靠顏色：
- 綠：一般民眾可投標、可正常過戶、資料健康
- 琥珀：未確認、需重新領牌、期限接近、需人工核對
- 紅：限回收商、僅供報廢、無法發動、同步失敗
- 藍：官方來源與證據

技術限制：Next.js App Router、React、TypeScript、Tailwind／CSS、lucide-react、shadcn/ui；不得在前端請求官方拍賣網站；照片使用私人快取或簽名 URL；介面語言 zh-TW；WCAG AA；鍵盤可操作；prefers-reduced-motion；手機底部 action 不可遮住內容。

請輸出：
1. 資訊架構與使用者任務說明。
2. 五個畫面的高保真設計。
3. component inventory 與 states。
4. design tokens。
5. desktop/mobile responsive 規則。
6. 可交給工程師的 React component 規格或程式碼。
7. 明確列出你保留的資料語意與你沒有自行推論的欄位。

驗收時請逐項對照 acceptance-checklist.md。不要生成假 logo、假車價、假照片、假同步成功狀態或不存在的來源覆蓋。
```
